# Functional Requirements

## 说明

- `P0`：首个可发布版本必须具备
- `P1`：首发后优先增强
- `P2`：可选增强，不能反向阻塞前两级

## FR-1 主机与组织模型

### P0

- `FR-1.1` 用户可以创建、编辑、删除 `Host`
- `FR-1.2` `Host` 至少包含名称、地址、端口、用户名、分组、标签和连接状态信息
- `FR-1.3` 用户可以按分组浏览主机
- `FR-1.4` 用户可以按标签筛选主机
- `FR-1.5` 用户可以按名称、地址、用户名、分组与标签搜索主机
- `FR-1.6` 用户可以从主机详情直接进入终端、SFTP 和相关操作

### P1

- `FR-1.7` 分组配置可以为主机提供继承默认值，例如 identity、jump host、startup snippet、终端外观、环境变量
- `FR-1.8` 主机支持更清晰的元数据展示，例如认证来源、路由来源、自动化配置来源

## FR-2 身份、凭证与信任

### P0

- `FR-2.1` 用户可以保存并复用 SSH identity
- `FR-2.2` 用户可以保存密码、SSH 私钥和证书
- `FR-2.3` 敏感信息必须进入凭证存储层，不能明文混入普通 JSON 持久化
- `FR-2.4` 用户可以为 Host 直接指定认证信息，也可以引用共享 identity
- `FR-2.5` 应用必须维护 Known Hosts，并在遇到未知主机或主机指纹变化时显式提示用户

### P1

- `FR-2.6` 支持 group-level identity inheritance
- `FR-2.7` 支持更完整的 SSH certificates 工作流

### P2

- `FR-2.8` 支持更复杂的硬件密钥或生物特征密钥集成

## FR-3 SSH 终端会话

### P0

- `FR-3.1` 用户可以从 Host 打开 SSH 终端
- `FR-3.2` 用户可以在多个终端会话之间切换
- `FR-3.3` 用户可以关闭、重连和查看会话状态
- `FR-3.4` 终端输入输出必须保留基本历史和可恢复上下文
- `FR-3.5` 应用必须把连接错误、认证错误和网络错误以用户可理解的方式展示出来

### P1

- `FR-3.6` 支持工作区内的会话筛选与恢复
- `FR-3.7` 支持会话日志的更强组织能力
- `FR-3.8` 支持终端主题、字号和继承设置

### P2

- `FR-3.9` 支持更多非 SSH 协议，例如 Mosh、Telnet 或 Serial

## FR-4 SFTP 文件工作流

### P0

- `FR-4.1` 用户可以从 Host 打开 SFTP
- `FR-4.2` 用户可以浏览目录、进入目录、返回上级目录
- `FR-4.3` 用户可以上传文件、下载文件
- `FR-4.4` 用户可以创建目录、重命名、删除文件或目录
- `FR-4.5` 文件操作失败时必须有明确错误反馈

### P1

- `FR-4.6` 增强大文件、重复覆盖和下载结果反馈
- `FR-4.7` 优化最近访问路径、目录恢复和更强的上下文保留

## FR-5 端口转发

### P0

- `FR-5.1` 用户可以创建本地端口转发规则
- `FR-5.2` 用户可以启停端口转发规则
- `FR-5.3` 用户可以看到规则所绑定的 SSH Host、本地端口和远端目标
- `FR-5.4` 失败的端口转发必须明确给出错误信息

### P1

- `FR-5.5` 支持远端与动态端口转发
- `FR-5.6` 支持更清晰的规则状态与冲突提示

## FR-6 命令片段与自动化

### P0

- `FR-6.1` 用户可以创建、编辑、删除命令片段
- `FR-6.2` 用户可以把片段发送到当前终端会话
- `FR-6.3` 用户可以在主机上下文里快速选择常用片段

### P1

- `FR-6.4` 支持 startup snippets
- `FR-6.5` 支持对多个主机或会话执行片段
- `FR-6.6` 支持 snippet packages 或更好的组织方式

## FR-7 工作区与上下文恢复

### P0

- `FR-7.1` 用户可以创建、命名、切换本地工作区
- `FR-7.2` 工作区可以组织多个终端会话
- `FR-7.3` 应用重启后应尽可能恢复工作区元数据和最近使用上下文

### P1

- `FR-7.4` 支持 workspace templates
- `FR-7.5` 支持工作区级命令广播
- `FR-7.6` 支持更清晰的工作区创建与管理流

## FR-8 日志与历史

### P0

- `FR-8.1` 用户可以查看基本会话日志或历史记录
- `FR-8.2` 历史应优先服务于“回到刚才做过的事情”，而不是审计合规

### P1

- `FR-8.3` 支持 log bookmarks
- `FR-8.4` 支持按主机或会话更清晰地浏览日志

### P2

- `FR-8.5` 如果未来引入同步，再考虑跨设备日志体验

## FR-9 搜索、过滤与导航

### P0

- `FR-9.1` 主机搜索必须足够快，且可在本地完成
- `FR-9.2` 标签筛选和分组浏览必须能组合使用
- `FR-9.3` 从列表到操作入口的路径必须短，避免多层深钻

### P1

- `FR-9.4` 为工作区、片段、日志增加更强的导航入口

## FR-10 本地持久化与恢复

### P0

- `FR-10.1` 非敏感数据使用本地持久化保存
- `FR-10.2` 敏感数据使用凭证存储层保存
- `FR-10.3` 数据模型变更必须保持向后兼容或提供安全迁移
- `FR-10.4` 应用不能因为单条坏数据而导致整个仓库不可用

### P1

- `FR-10.5` 引入更细粒度的恢复与迁移测试
- `FR-10.6` 如果未来加入个人同步，必须保持本地离线可用

## FR-11 个性化与体验增强

### P0

- `FR-11.1` 基础界面必须能在手机和平板上可用
- `FR-11.2` 常见 destructive actions 必须二次确认

### P1

- `FR-11.3` 支持终端主题
- `FR-11.4` 支持字号配置与继承
- `FR-11.5` 支持环境变量注入
- `FR-11.6` 支持 jump host / host chain

## 明确排除的功能需求

以下内容不应出现在需求实现中，除非产品方向被重新定义：

- 共享 Vault
- 成员邀请
- 协作编辑
- 多人同时查看或操作同一终端
- 组织角色与权限系统
- 企业后台
- 统一计费
- 组织审计报表

## 需求裁剪规则

如果新需求同时满足下面任意两项，应先拆成新 spec，而不是直接实现：

- 涉及两个以上核心子系统
- 需要引入新的持久化结构
- 需要引入新的外部服务或账号体系
- 需要新增团队或组织概念
